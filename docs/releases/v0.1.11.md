# v0.1.11

从 `feat/authority-permissions` 功能分支发布，修复权限快照与目录条目版本失配后持续无法挂载的问题，
并将 Common 依赖固定为正式发布的 **v2.0.0-alpha4**。最低 Go 版本继续为 **1.27.4**。

## 修复与调整

- **失配主动恢复**：目录条目与快照 generation 不一致时，真正重新获取权限快照并有界重试，
  避免重复读取旧缓存导致挂载持续返回500、上层实例创建返回503。
- **覆盖全局版本变化**：ToolFS 订阅全部权限事件，覆盖路径、用户组、角色、应用归属等依赖；
  不将对象命名空间误当成完整的授权依赖范围。
- **严格校验与失败保护**：主体不一致立即拒绝；版本配对最多三轮，持续变化或刷新失败时结束
  本次请求，不回退用户权限或旧授权。错误包含两边版本号。
- **判断缓存正确失效**：使用 Common 的本地 `CacheRevision` 感知快照移除和同版本恢复，
  防止强刷失败后继续复用旧 allow，或恢复后继续复用旧 deny。
- **保持文件操作走内存**：普通文件操作不新增 HTTP 请求，已有视图、根 fd 和 inode 继续按差异复用。
- **依赖正式版本**：从 Common 的临时提交版本切换到 `v2.0.0-alpha4`，没有本地 replace 依赖。

## 验证与性能

- 使用正式 Common alpha4 的完整 race 测试及 `go vet` 已通过。
- 75 上8项隔离真实 FUSE／恢复测试通过且无跳过，覆盖挂载生命周期、用户隔离、存储拓扑与 cwd、
  应用授权、无事件失配恢复、同版本判断缓存恢复及全局订阅。
- 同实现的候选版本已在75通过临时 bind 接入：挂载返回201，实际实例创建返回200，用户确认恢复。
  这不等同于 v0.1.11 正式安装包已部署。
- 同机5轮中位数，已热文件判断从31.67变为31.85 ns/op，约增加0.6%，仍为零 HTTP、零分配。
  全局事件重热1／8个主体分别为85.784／564.983 µs，产生1／8次 HTTP；本机模拟数据不含真实
  权限数据库和完整视图重建耗时。
- [完整性能边界及原始数据](../permission-refresh-performance.md)。标签流水线继续要求四项真实 FUSE
  用例实际通过，并执行只读系统安装检查和 Linux amd64／arm64 打包；跳过不能代替通过。
